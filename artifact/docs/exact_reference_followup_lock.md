# Exact stepwise coefficient-matched reference follow-up

Status: prospectively locked before inspecting any outcome from seeds
4101--4112.

## Question and scope

The conventional no-replay arm gives the current minibatch coefficient one,
whereas ER averages the current and replay examples in one concatenated loss.
The earlier fixed-current arm approximates the usual full-buffer coefficient
by changing the learning rate.  This follow-up adds a current-only arm that
matches ER's current-example coefficient on every update, including the empty
buffer, buffer warm-up, and partial-final-minibatch cases.

If the current minibatch contains \(b_{c,t}\) examples and ER would draw
\(b_{r,t}\) replay examples, the new arm uses

\[
  a_t = \frac{b_{c,t}}{b_{c,t}+b_{r,t}},
  \qquad
  L_t^{\mathrm{exact}} = a_t\,\overline L_{c,t}.
\]

It samples no replay examples and advances no replay-sampling RNG.  A shadow
occupancy counter implements the same buffer-cardinality schedule as ER.  A
per-update audit records the current size, shadow occupancy, counterfactual
replay size, and coefficient.

This arm isolates the current-loss coefficient more exactly than nominal
learning-rate rescaling.  It does **not** reproduce replay-induced batch
composition, batch-normalization state, replay gradients, or the subsequent
parameter trajectory.  Consequently it is an exact coefficient control, not
a claim to match every effect of replay.

## Frozen unit inventories

All comparator arms are rerun on twelve fresh run seeds, 4101--4112.  The
historical result trees remain immutable.

### Permuted MNIST

For each seed, the 20 mandatory units are:

- standard no replay: 1;
- nominal fixed-current no replay: 1;
- exact stepwise coefficient-matched current only: 1;
- paired ER at assignment strength zero: 1; and
- reassigned ER: four replicas at each of 0.25, 0.50, 0.75, and 1.00: 16.

Thus the PMNIST campaign contains \(12\times20=240\) units.  Every arm for a
seed uses the same pre-generated, RNG-isolated task bank.  The twelve bank
digests are stored in `configs/exact_reference_pmnist.json` and regenerated by
the protocol validator.

The three confirmatory seed-level contrasts are paired minus exact,
lambda-0.75 replica mean minus exact, and lambda-1 replica mean minus exact.
Positive values favor the replay arm.  Two-sided p-values are Holm-corrected
over these three tests.  Conventional/fixed controls, the full dose response,
and all other contrasts remain reported descriptive results.

### Split CIFAR-100

For each of twelve seeds and each of the six previously locked class streams,
the eight mandatory units are:

- standard no replay: 1;
- nominal fixed-current no replay: 1;
- exact stepwise coefficient-matched current only: 1;
- paired ER at assignment strength zero: 1; and
- fully reassigned ER: four assignment replicas.

Thus the CIFAR campaign contains \(12\times6\times8=576\) units.  Contrasts
are averaged over the three orders within each order family and seed before
seed-level inference.  The confirmatory family contains paired minus exact
and lambda-1 replica mean minus exact in each of the two order families:
four two-sided tests with Holm correction.  Positive values favor replay.

Together the campaigns require exactly 816 unique PASS-sealed units.  No
scientific aggregate may be built from partial coverage, and there is no
outcome-dependent stopping.

## Parallel execution on the 32 GiB server GPU

The two campaigns run sequentially; only units within a campaign run in
parallel.  CUDA MPS is not enabled.  Every subprocess retains the locked four
DataLoader workers and one numerical thread.

The PMNIST adaptive ceiling is 20 GPU processes, with 1,536 MiB reserved per
candidate launch.  The CIFAR ceiling is 9, with 3,400 MiB reserved per
candidate launch.  Both require a GPU with at least 32,000 MiB total memory,
retain 1,024 MiB free, stagger launches by five seconds, and query live GPU
memory before every launch.  At most one admitted child may remain in its
CPU-only preflight before a process in its owned group appears in the CUDA
compute-process table.  This lets steady-state concurrency ramp to the locked
width without admitting a wave of not-yet-visible CUDA allocations.  A launch
is admitted only when

```
free_mib >= reserve_free_gpu_memory_mib + per_process_launch_reservation_mib
```

Before opening each pool, the coordinator runs one exact-control and one
high-memory reassigned-replay unit serially through the real pinned Mammoth
and data path.  It measures incremental peak VRAM, requires both pilots to fit
the campaign's per-process reservation, and reuses their authenticated unit
seals in the full campaign.  The ceilings therefore do not force unsafe
occupancy.  They allow the queue to fill the RTX PRO 4500's 32,623 MiB
opportunistically while the live gate holds new admissions when observed free
memory is insufficient.
With `--workers auto`, the reservation calculation resolves to the locked
ceilings of 20 PMNIST workers and 9 CIFAR workers on that card.  Twenty-one
PMNIST reservations or ten CIFAR reservations cannot coexist while preserving
the locked live-memory floor, so these are the highest defensible widths under
the per-process bounds.  The reported width remains an admission ceiling,
never a promise that every slot will be resident simultaneously.  The PMNIST
ceiling can create at most 80 DataLoader workers and the CIFAR ceiling at most
36; operational monitoring must include host RAM and process load in addition
to VRAM.

The pinned Mammoth parser uses `drop_last=0`, so the partial final minibatch is
retained.  The exact-arm audit must therefore contain 9,380 optimizer updates
and 1,200,000 seen current examples for PMNIST (469 updates per task, 60,000
examples per task), or 1,580 updates and 50,000 seen examples for CIFAR (79
updates per task, 2,500 examples per task).  Any short or extra audit is a
failed unit.

When any unit fails, the queue stops launching new units, drains already
running processes, preserves failed attempts, and emits no aggregate.  On
restart it authenticates existing PASS seals and schedules only missing units.
